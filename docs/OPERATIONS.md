# 本地运营台

服务运行后，在服务器本机访问 `http://127.0.0.1:26042/`（主端口 +2）。Windows 启动器也可打开 Admin；无桌面的服务器可通过 SSH 转发访问。后台不开放公网登录。

| 页面 | 操作 |
| --- | --- |
| 运行概览 | 玩家／绑定／游客数量，近期活跃估算、组队连接与房间、近期单人未结算、业务请求耗时及错误 |
| 账号管理 | 按绑定、活跃、注册／登录时间筛选，查看资源／库存／进度及对局摘要；绑定／解绑、密码重置、登录封禁和管理邮件 |
| 任务与成就 | 设置普通、期间限定和活动任务的条件、奖励和开放时间 |
| 礼物发放 | 选择玩家、奖励分类与职业筛选、批量发放；“全选本页”和“取消本页选择”只处理当前页，其他页保留 |
| 卡池 | 配置消耗道具、价格、内容与概率；在“扭蛋发布”控制开放，固定新手单抽／连抽不受运营池开关影响 |
| Boss 发布 | 活动／素材与往期分 Tab，目录开放名单／排期；按难度设置入口和复活，查看各波部位属性；支持全部关闭 |
| Boss 掉落 | 按难度、波次、部位设置奖励；同难度两种模式共用掉落，可复制到同组其他难度 |
| 道具商店 | 按页签配置商品、支付方式、价格、每份数量、累计及周期限购；已拥有的永久表情在游戏中隐藏 |
| 兑换所配置 | 修改商品、价格、限购和上下架；复制、删除／恢复兑换所，批量添加素材；兑换次数保留 |
| 圣剑杯与探索 | 计分档位及固定奖励、回合上限、组队起始COST与倍率；探索随机奖励 |
| 卡牌进化链 | 查看卡牌形态与进化路线，独立开关每个进化方向；默认全部开放 |
| 运营设置 | 登录白名单、IP 黑名单、游戏功能开关、组队倍速和首页轮播 |
| 运行日志 | 按时间、级别、接口、请求 ID 或玩家 UID 搜索本次运行日志 |
| 维护工具 | 维护开关、无引用运营状态清理、卡池永久删除、按时间范围清理审计历史 |
| 公告与奖励 | 公告、签到奖励、新手毕业邮件、剧情首通奖励、看板价格与购买开关 |

点保存才会写入 SQLite 公共运营配置，重启保留；多人同时编辑发生版本冲突时应刷新后重新编辑。默认值来自随包配置，数据库中已保存的运营设置优先。此类改动不需要重新上传 CDN。

BOSS详情按难度配置“单人／组队”和“单人（仅自己的卡组）”，可同时开放；独立普通BOSS的自卡组模式复用同一难度配置，新补充的入口默认关闭，勾选保存后开放。允许复活为独立选项，保持原费用。规则用于后续开战，不改变已开始的战斗。关闭入口不清除通关记录；掉落与名声池按难度共用。目录排期控制展示，并非逐个BOSS的入场截止时间。

兑换所删除后从游戏隐藏，后台仍可恢复；恢复后默认关闭，核对后再开放。原商品ID及累计兑换次数不变，复制成新兑换所则使用新的限购身份。卡池、掉落、兑换方案支持导入／导出；卡牌可按职业、星级、属性、COST、来源及资源状态筛选。

组队默认1.5倍，运营修改只影响新建房间，旧房间及重连沿用建房时倍速。选牌倒计时和单人倍速不变。下一回合开始时仍死亡的真人退出房间，场上角色保持死亡并由AI路径处理，不获得本局奖励，也不贡献全队共用名声奖励；在此之前已复活的玩家继续参战。

玩家总数包含绑定账号和游客，不含系统伙伴。活跃人数合并最近5分钟成功业务请求及组队连接，按UID去重；组队对局只统计已连接真人，不把AI／掉线席位当在线玩家。单人为近期有请求且未结算的估算，不能视为精确实时在线。请求统计不含资源下载、登录鉴权失败及HTTP 200中的业务拒绝，重启重新累计。

新手十一连固定从12张初期卡抽取，5星为加荷里斯、佩里诺亚、丽奈特、奥尔特莉特，另有8张4星；原保底和仅一次规则保持，不在后台配置。

误发邮件可通过“账号管理 → 管理邮件”搜索，按未领取／已领取筛选，再单封或批量删除，每次最多100封。无需先领取即可删除；已领取的奖励不会回收，删除记录写入审计。同一批发放的请求重试不会恢复已删除邮件。

“卡池配置”的各分池独立设置卡牌、权重、名声、价格和消耗方式，封面及开始／结束时间整池共用；开放统一在“扭蛋发布”控制。新建时可选择规则模板，阶段池可逐阶段配置消耗道具。职业池按所选职业的有效卡牌及相对权重归一化抽取；后台保存／发布会拒绝可抽职业没有有效卡牌的配置。

混合职业分池可一键按职业分配到相同抽法的职业分池；预览先列出将替换的卡牌数量，没有匹配卡牌的职业会跳过并保留原配置。也可复制当前分池内容到其他分池。累计限抽由整池共享，每次成功抽取计一次，十连同样计一次；达到限额后仍可查看卡池。每日限抽按北京时间 0 点重置。

扭蛋入口按卡池组设置。单抽、连抽和职业分池共用分类与排期，各抽法单独设置消耗、奖池及附赠。自选卡池须选满指定张数后才能抽取。固定或随机附赠通过邮件发放。首页轮播跳转使用卡池组，卡池组没有可见抽法时对应横幅隐藏。

普通页签用于长期成就，可选存档状态或指定目标。期间限定和活动页签使用动作计数，例如强化、探索或成功通关。期间限定须设置每日重置或结束时间，活动须设置结束时间。草稿可以先保存，预览和发布前需要补齐条件、奖励和开放规则。

通过随包启动器或启动脚本运行服务时，运营台会接入当前日志。使用运行日志页的时间范围、请求 ID 和玩家 UID 可以缩小搜索范围。

道具可按名称或ID搜索，价格和预览显示实际名称。友情点池保留按余额决定连抽数、每日首次免费的规则；改用其他消耗方式时不再套用这些友情点规则。草稿发布或放弃后清除草稿正文；删除的卡池在回收站中可恢复，永久删除需开启维护并先预览。

玩家列表、赠礼目录、兑换商品和奖励弹窗均支持取消本页选择；原“清空选择”会取消全部页。掉落页切换筛选保留草稿，并显示正在编辑的副本。

侧栏“未保存”标记配置草稿，切换页面会保留，刷新或关闭浏览器会提醒。卡池／兑换所筛选不改变当前编辑对象，以“正在编辑”的名称和ID为准。掉落页可组合属性、难度和关键词筛选。资源发放等待响应时不能关闭弹窗或修改内容；失败可按原内容重试，结果不明时先核对账号／审计，避免另建操作。

普通签到每7次循环，新手签到发一轮，累计登录奖励独立计数。调整奖励不重置已领取记录，剧情首通奖励不补发给已通关账号；停售看板不回收已有看板，已开战的副本沿用原奖励计划。

新手毕业邮件默认关闭。可配置标题、正文，批量选择货币、卡牌、素材、道具、召唤石和传承卡，修改数量与卡牌等级／名声／忠诚度。完成全部九步新手训练后，按当时保存的配置发放一次，每种奖励一封邮件（最多120种）。注册、重登和初始战斗不会提前发送；已完成训练的账号不补发，重试不重复发放。背包满时可以稍后领取。

月卡与无穷卡目前是免费本地商品，不扣水晶。购买到账开关也控制购卡立即赠送的250／600水晶；关闭时仍开通卡权益。
月卡按北京时间计算30个领取日，续购累加天数；无穷卡永久有效。两张卡各自每天最多领取100水晶，购买次数不叠加每日收益，不重置当天领取记录，漏领不补。无穷卡重复购买不再发放600水晶。

好友容量按等级成长，默认配置最高65；关注容量至少覆盖该上限，原有更高配置保留。系统伙伴也占关注名额，互相关注成为好友，沿用原生关注／互关流程。达到容量时返回正常提示。

推荐伙伴从好友／关注及最近活跃的100名其他玩家中按职业分配，缺少对应职业时使用系统伙伴。组队战斗中的伙伴按佣兵、富豪、盗贼、歌姬的固定顺序排列，自身单独显示。

仓库默认3000格，旧账号的小容量在加载时补齐，更高值保留。持有卡牌及仓库均可通过原生扩容入口增加容量，最高6000格。体力药允许恢复后超过自然上限，超过上限时暂停自然恢复。

圣剑杯单人沿挑战本规则：通关领取全部未领取档位，失败、超时或退出无奖励；组队按本局权威战斗计分。组队起始COST可配置3–10，缺省为3，单人起始COST保持客户端规则。回合上限对两种模式生效，0表示不另设上限；新规则影响后续入场，已开战使用开局配置。

进化限制只判断本次“起点卡 → 目标卡”的直接路线；同星级双向互转分别控制。未配置默认开放，受限时返回游戏弹窗且不扣材料、金币；不会回收玩家已有卡牌。

“大家都通关卡组”展示近期真实通关样本，昨天单人／多人排行按通关次数统计。服务启动会自动补建新增统计表及索引，保留已有数据库；统计从更新后的通关开始，无法从旧的永久通关标记补出历史日期与卡组。展示统计滚动保留30天，不影响永久通关记录。

维护工具仅允许在维护开启且请求排空后执行清理，流程为预览、备份、执行。只清理彻底删除且无配置引用的运营状态；过期、下架或可恢复配置的计数保留。BOSS通关、剧情进度、货币库存及领奖收据不在清理范围。审计历史按时间范围单独清理。结束后需手动关闭维护。

备份时正常停止服务，保存完整 `_local/data/` 以及自己的 `cdn.json`、`cdn-sync.json` 和连接设置。不要把玩家数据或填写过密钥的配置放进源码仓库。

## 运营图片同步

Windows／Linux 启动脚本通过 `-cdn-sync-config` 读取运行目录的 `cdn-sync.json`。填写存储上传地址、桶和访问密钥后重启服务，在「维护工具 → 同步运营图片到存储容器」依次检查、同步、启用。公开读取地址来自「运营设置 → 上传图片来源」。游戏资源上传另用 `Sync-CDN.cmd` 或 `Sync-CDN.sh`，详见 [CDN 配置](resources/CDN.md)。

文件缺失或保留未填写的示例时，后台同步功能关闭；配置有误时后台显示原因。上传和启用由后台操作触发。

## 账号缓存容量

启动前设置环境变量 `KAIRI_ACCOUNT_CACHE_LIMIT` 可调整空闲账号处理器数量，默认32，范围0–4096（0禁用空闲缓存）。Windows启动器和Linux启动脚本均继承此变量；修改后重启服务端生效。PowerShell示例：`$env:KAIRI_ACCOUNT_CACHE_LIMIT='64'`，随后在同一终端启动服务；Linux示例：`KAIRI_ACCOUNT_CACHE_LIMIT=64 sh Start-Server-linux-amd64.sh 192.168.1.100`。

请求结束即进入空闲缓存，超过数量先淘汰最久未用项；5分钟未使用也会回收。请求执行中的账号不淘汰。增加容量以更多内存换取较少的重复加载；不是在线人数限制。

新手毕业邮件选择卡牌后，可用“全部满级／全部满名声”按各卡自身上限批量填写；检查后保存生效，不影响已有领取记录。
