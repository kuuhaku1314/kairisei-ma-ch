# 活动与往期副本体力、经验配置

后台入口为“Boss 发布 → 体力与经验”。3D 活动副本、2D 活动和往期副本的同名难度共用覆盖值；普通主线、塔层和钥匙素材本不参与。自卡组入口跟随对应难度。接口沿用 Admin 的登录、本机访问限制、写请求保护及操作审计。

范围由配套资源中的活动与往期目录决定，与当前开放名单无关。难度名称和副本数量取自当前资源，调用方不应自行维护枚举。

## 读取

`GET /api/boss-economy` 返回版本、难度、限制与目录范围：

```json
{
  "state": "PASS",
  "revision": 0,
  "rules": [{
    "difficulty": "超弩级",
    "boss_count": 12,
    "defaults": {"bp_use": [45], "bp_use_half": [23], "experience": [900]},
    "current": {"bp_use": [45], "bp_use_half": [23], "experience": [900]},
    "override": null
  }],
  "limits": {"bp_use_min": 1, "bp_use_max": 1000, "experience_min": 0, "experience_max": 10000000},
  "directories": ["activity_3d", "activity_2d", "past"],
  "half_rounding": "ceil"
}
```

上例数量仅为示意。`boss_count` 按实际副本去重，不重复计算其自卡组入口。

`defaults` 为资源默认值，`current` 为覆盖后值。数组长度大于 1 表示同难度下各副本原本不同；显示全部默认值，不能取第一项写回。`override` 非空时只包含已明确覆盖的字段，另一字段继续沿用默认值。

## 保存与重置

`PUT /api/boss-economy` 批量修改 1–100 个难度，提交读取时的版本：

```json
{
  "expected_revision": 0,
  "rules": [
    {"difficulty": "超弩级", "bp_use": 45, "experience": 900},
    {"difficulty": "地狱级", "bp_use": 60},
    {"difficulty": "Lv1", "reset": true}
  ]
}
```

- 每行替换该难度的整份覆盖。省略字段或传 `null` 表示该字段沿用默认值；至少明确设置体力或经验之一。
- `reset: true` 删除该难度覆盖，不能与数值字段混用。请求未列出的难度保持不变。
- 单人体力为 1–1000 的整数，拒绝 0 和负数。组队建房消耗为 `ceil(单人体力 / 2)`，只读显示；队员沿用原有费用规则。
- 通关经验为 0–10000000 的整数。0 表示不给通关经验，金币、掉落、名声及首通奖励保持。
- 未知难度、重复行、缺版本、越界或非法组合返回 400；版本冲突返回 409。整批校验和持久化成功后才生效。
- 成功返回 `{"state":"PASS","revision":1}`，调用方应重新读取。恢复默认使用资源值，不是清零。

## 生效与持久化

保存后玩家下一次请求读取新值，已打开的列表需重新获取。已开战的体力按原入场记录冻结，不重复扣除；通关经验按结算请求当时生效的配置发放。

覆盖保存在运营数据库的 `boss-economy` 文档中，重启后保留，不改写资源包或玩家历史记录。审计操作分类为 `boss-economy`。升级资源后，已保存的覆盖继续优先，恢复默认才使用新资源的值。
